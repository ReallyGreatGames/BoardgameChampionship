# `lib/i18n/i18n.ts`

[← lib/i18n](README.md)

## Purpose

Initializes the app's i18next instance and picks the active language at startup.

## Exports

| Export | Type | Purpose |
|---|---|---|
| `LANGUAGE_STORE_KEY` | `string` (literal `"app_language"`) | The key under which the language choice is persisted in [`secureStorage`](../secureStorage.md) |
| `default` | `i18n` (i18next instance, from `i18next`) | The configured, already-initializing i18next instance, bound to `initReactI18next` for use with `react-i18next` hooks (`useTranslation`, etc.) |

`LANGUAGE_STORE_KEY` is a plain string constant with no parameters —
imported by both this module (to read the stored language on startup) and
by [`app/(pages)/settings.tsx`](../../app/(pages)/settings.md) (to persist
the user's language choice). The default export is the i18n singleton
itself, not a function — components consume it indirectly via
`react-i18next`'s `useTranslation()`, or call `i18n.changeLanguage(lang:
string): Promise<TFunction>` on it directly to switch languages at runtime.

## How it works

On module import, i18next is initialized with the `de`/`en` resources
([translations/de.ts](translations/de.md), [translations/en.ts](translations/en.md)),
defaulting to `de`. Afterwards, `getItemAsync(LANGUAGE_STORE_KEY)` is used to
asynchronously check the [SecureStore](../secureStorage.md) for a
previously chosen language: if found, it's activated via
`i18n.changeLanguage`; otherwise the system language is used via
`expo-localization`'s `getLocales()` (German if the system locale is `de`,
English otherwise).

## Used by

- [`app/_layout.tsx`](../../app/_layout.md) — imports this module to initialize i18next globally
- [`app/(pages)/(team-player)/choose-your-character.tsx`](../../app/(pages)/(team-player)/choose-your-character.md)
- [`app/(pages)/settings.tsx`](../../app/(pages)/settings.md) — language switcher, calls `i18n.changeLanguage` and writes `LANGUAGE_STORE_KEY`
